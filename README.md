# MusicTalk reproduction

## Paper and scope

Primary paper: Lin, Cheng, and Chiu, “MusicTalk: A Microservice Approach for Musical Instrument Recognition,” *IEEE Open Journal of the Computer Society*, vol. 5, pp. 612-623, 2024. DOI: [10.1109/OJCS.2024.3476416](https://doi.org/10.1109/OJCS.2024.3476416). The NYCU publication page provides the paper abstract and bibliographic record; the author manuscript is indexed on ResearchGate.

Model references: the paper builds on [PaSST](https://github.com/kkoutini/PaSST) for the ViT branch and [PANNs](https://github.com/qiuqiangkong/audioset_tagging_cnn) for the ResNet38 branch. No MusicTalk-specific author repository was located; these upstream implementations do not contain the paper's BCP-WP ensemble wiring.

The local upstream snapshots are pinned in [`vendor/README.md`](vendor/README.md). The official PaSST OpenMIC example exposes a 20-tag PaSST configuration and embedding output; PANNs provides the ResNet38 log-mel branch with a 2048-dimensional embedding. The MusicTalk-specific BCP-WP sampler and PaSST/ResNet fusion are locally integrated in `bcp_wp.py` and `train_dual_branch_smoke.py`; this remains a paper-guided reimplementation because no MusicTalk-specific author repository was located.

The paper combines a ViT with brightness-characteristic patchout (BCP-WP), CNN detectors, and a multi-dataset audio shaper. It reports OpenMIC-2018 experiments and additional strong-label evaluations using MedleyDB, URMP, and INSTDB. The first pass is deliberately smaller: establish an OpenMIC data loader and one bounded training run, not all detector/data-source combinations or repeated seeds.

## Reproduction gates

1. Verify the OpenMIC archive checksum and inspect its supplied splits and labels. **Complete.**
2. Run one short training smoke experiment on official VGGish features, with masked and class-weighted BCE. **Complete;** that VGGish-only run left the official test partition untouched.
3. Integrate the paper's Mel-spectrogram, PaSST + BCP-WP, and ResNet ensemble. **A frozen-backbone, one-epoch integration pilot now completes on raw OpenMIC audio.**
4. Extend one variable at a time after reviewing the pilot; keep the additional datasets and microservices out of this first model-only reproduction.

Do not compare a capped smoke run directly with the paper's full-dataset headline scores.

## Latest short full-split run

- A WSL/RTX 3090 paper-guided fine-tuning run completed all 13 requested epochs on OpenMIC raw audio: 12,677 train / 2,238 validation items, batch size 4, seed 17, and both pretrained backbones unfrozen. It stopped at the deliberate 13-epoch cap, not at patience convergence; this is a short single-seed development reproduction, not the paper's 20-epoch article protocol or the author repository's 150/200-epoch examples.
- Best checkpoint: epoch 5, selected by validation weighted masked BCE (0.34725). At that checkpoint, validation macro ROC-AUC was 0.92361, mAP 0.86604, and ROC-nearest-threshold macro-F1 0.82591 over 20 classes.
- One official OpenMIC split01 test inference was then run using validation-selected class thresholds, with no test-threshold tuning: 5,085 clips, 10,522 observed labels, macro ROC-AUC 0.91549, mAP 0.85127, and macro-F1 0.79760. The official test partition had already been evaluated once for a different one-epoch checkpoint earlier in this project, so this is not an untouched independent final test; that exposure is recorded in the test metrics.
- Training config, history, split IDs, checkpoint, and full train log are in `runs/paper_aligned_openmic_pat10_cap13_seed17_20261011/` and `runs/paper_aligned_openmic_pat10_cap13_seed17_20261011.train.log`. Test metrics, per-item predictions, and evaluation log are in `runs/official_test_pat10_cap13_seed17_20261011/` and `runs/official_test_pat10_cap13_seed17_20261011.log`. The checkpoint SHA-256 is recorded in the test `metrics.json`.
- The evaluator needed a narrow PyTorch 2.10 safe-unpickling allowlist for the inert `torch.torch_version.TorchVersion` metadata stored by this local training run. `weights_only=True` remains enabled.

## Best-checkpoint branch follow-up (2026-10-11 to 2026-10-12)

- A follow-up branch started from the full-split run's best epoch-5 checkpoint, reused its exact train/validation IDs, and used seed 17 with the recorded optimizer hyperparameters. Since the source checkpoint did not contain optimizer or RNG state, this initialized a new AdamW optimizer and reseeded the RNG; it is a best-checkpoint fine-tuning branch, **not an exact resume** from epoch 13.
- The first attempt was manually stopped during epoch 11 at batch 3,000/3,170. Its completed history covers epochs 6–10 only; its best checkpoint remained epoch 5. That interrupted run and its log are kept under `runs/paper_aligned_openmic_branch_from_best5_to20_seed17_20261011/` and the adjacent `.train.log`.
- A separate clean branch then trained epochs 6–15 and stopped when patience 10 was reached (20 was the cap). Validation loss did not improve over the source checkpoint in any of those ten epochs. Best remains epoch 5: validation weighted masked BCE 0.34725, macro ROC-AUC 0.92361, mAP 0.86604, and ROC-nearest-threshold macro-F1 0.82591.
- The clean branch did not evaluate the official test partition. Its config, epoch history, stop metrics, checkpoint, and training log are in `runs/paper_aligned_openmic_branch_restart_best5_to20_seed17_20261011/` and the adjacent `.train.log`.
- This follow-up confirms that the best-epoch checkpoint did not benefit from another ten epochs under this setup. Both the original 13-epoch run and this reset-state branch are short, single-seed, paper-guided experiments; neither is a full or exact reproduction of every MusicTalk experiment.

## Current status

- CUDA: RTX 3090 available through the existing PyTorch CUDA environment.
- OpenMIC archive: downloaded, MD5-verified (`e4ccf187e2bb5ab2e115416e8aafe7f4`), and extracted to `../0_dataset/processed/openmic-2018`. The official NPZ has 20,000 samples with `X (20000,10,128)`, `Y_true (20000,20)`, and `Y_mask (20000,20)`; official partitions are `split01_train.csv` and `split01_test.csv`. VGGish's official postprocessor clips embeddings to `[-2,2]` and quantizes them to `[0,255]`; the smoke loader now reverses that affine quantization before training.
- Author source code: no official MusicTalk implementation has been located yet; the paper's method will be reimplemented and clearly tracked as such.
- PaSST and PANNs source snapshots are pinned in `vendor/README.md`; official AudioSet checkpoints are in `weights/README.md`. Both checkpoint structures and published integrity hashes are verified. An isolated dependency set is staged under `vendor/python_deps`; PaSST, PANN ResNet38, both official checkpoints, and CUDA frontends initialize on the RTX 3090.
- `bcp_wp.py` implements the paper's weighted brightness sampling without replacement as a standalone ViT patch-selection primitive: it keeps `K-K*` patches sampled with probability `b_k / sum(b)`, then drops the `K*` candidates left over. It has passed a small CUDA tensor smoke check.
- `train_smoke.py` is a deliberately simplified MLP over the supplied VGGish features. It exercises the official split, binary relevance labels thresholded at 0.5, missing-label masks, inverse-frequency weighted BCE, logging, and checkpoint path; it is not a reproduction of the PaSST + BCP-WP + ResNet ensemble. The loader recognizes separate `Y_mask`, concatenated 20-target/20-mask matrices, NaN masks, and OpenMIC's neutral-0.5 missing-label sentinel.
- Corrected real-data smoke run completed on CUDA, one seed, one epoch, 1,024 train / 256 validation examples, after VGGish feature dequantization. Validation masked weighted BCE 0.4890, macro ROC-AUC 0.8713, mAP 0.7910, and ROC-tuned macro-F1 0.7993 across 20 classes. Exact settings, metrics, and checkpoint are in `runs/smoke/`; the official test partition was not evaluated. These are development checks only, not paper-comparable results. The earlier first-pass metrics on raw quantized features were superseded and should not be compared.
- `train_dual_branch_smoke.py` reads raw 10-second OGG clips, uses the PaSST Mel frontend and PANN ResNet38 frontend, retains 9 of 12 PaSST frequency patches with brightness-weighted BCP-WP during training, and fuses the two 20-class probabilities through a 40-to-20 linear layer. The AudioSet backbones are frozen in these short runs; only the OpenMIC heads and fusion layer update. This is not full MusicTalk training.
- A full-split, one-epoch dual-branch run completed on the RTX 3090: 12,677 train / 2,238 validation, batch 8, seed 17; the training loop took 481.23 s. Weighted masked BCE was 0.56389 train / 0.47011 validation. Validation macro ROC-AUC 0.91724, mAP 0.85750, and ROC-nearest-point macro-F1 0.81304 across all 20 classes (4,611 observed validation labels). Exact config, thresholds, sample IDs, and trainable heads are in `runs/official_split_one_epoch/`; the full log is `runs/official_split_one_epoch_run.log`.
- A three-epoch full-split fine-tuning run completed on the RTX 3090: 12,677 train / 2,238 validation, batch 4, seed 17, with both pretrained backbones trainable; total training-loop time was 2,476.9 s. The best validation checkpoint was epoch 3: masked weighted BCE 0.36715, macro ROC-AUC 0.92305, mAP 0.86899, and ROC-nearest-point macro-F1 0.82571 across all 20 classes (4,611 observed labels). This is a capped single-seed development run; patience-based convergence was not reached and the official test partition was not evaluated. Config, split IDs, epoch history, metrics, and checkpoint are in `runs/paper_aligned_openmic_finetune_3ep_seed17_20261011/`.
- After freezing that checkpoint, `evaluate_openmic_test.py` scored the official 5,085-item test partition once, without further training or test-threshold tuning: macro ROC-AUC 0.90907, mAP 0.83811, and macro-F1 0.79436 using thresholds selected on validation (10,522 observed labels; all 20 classes scored). Predictions, metrics, and split checks are in `runs/official_test_one_epoch/`; run log: `runs/official_test_one_epoch_run.log`. This is a held-out evaluation of a one-epoch development checkpoint, not a paper-length reproduction.
- The 512/128, 128/32, and 12/4 smaller runs are also retained as progression checks. Every dual-branch result is single-seed and one epoch with frozen AudioSet feature backbones; only the OpenMIC branch heads and fusion layer update. It is not the paper's complete training protocol or a paper-comparable result.
- On this Windows CUDA setup, `torchlibrosa`'s librosa wrappers for the Hann window and mel filter stalled during PANN initialization. The local dependency copy now uses SciPy periodic-Hann construction and torchaudio's Slaney mel-bank conventions; standalone frontend shape checks and the pretrained ResNet38 load pass. The compatibility scope is documented in `vendor/README.md`.
